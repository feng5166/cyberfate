## 一、桌宠形态概述

### 1.1 什么是"桌宠"

桌宠（Desktop Pet）是一种常驻在用户设备上的虚拟角色交互产品：
- **PC 端**：角色在桌面最上层自由活动/趴伏，可点击/拖拽/互动
- **手机端**：以 Widget / 悬浮窗 / App 内常驻 / 锁屏等形式存在
- 代表案例：Bongo Cat、Shimeji、XP Office 助手、早期电子宠物

### 1.2 为什么考虑桌宠

v2 方案的核心论点是：**CyberFate 需要从"工具"变成"陪伴"**。

但 Web 网站有一个根本局限——**用户不打开网站，阿道就不存在**。

桌宠解决了这个问题：**阿道一直在那里，无论你有没有主动打开它。**

这不是功能升级，这是产品形态的根本性变化。

### 1.3 本文档目标

回答一个关键决策问题：
> **桌宠应该替代 Web 版成为核心产品形态，还是作为 Web 版的补充功能？**

## 二、PC 端桌宠产品设计

### 2.1 技术选型

| 维度 | Electron | Tauri | 推荐 |
|------|----------|-------|------|
| 包体积 | ~80-150MB | ~3-8MB | **Tauri ✓** |
| 内存占用 | ~100-200MB | ~30-50MB | **Tauri ✓** |
| 开发语言 | JS/TS (Node) | Rust 前端 + JS/TS | Tauri 学习成本略高 |
| 生态成熟度 | 极成熟 | 成熟快速成长中 | 都够用 |
| 像素渲染性能 | 够用 | 更优 | **Tauri ✓** |
| Windows 兼容 | 好 | 好 | 平手 |
| macOS 兼容 | 好 | 好 | 平手 |
| 发布渠道 | GitHub Releases / 自建 CDN | 同左 | 平手 |

**结论：推荐 Tauri v2**
- 包体小 10-20x → 用户下载门槛低
- 内存占用低 → 用户不会因为占资源就关掉
- 对"常驻后台"类产品来说这两点是生死攸关的
- 前端可以用现有的 Next.js 代码复用（Web View 层）

### 2.2 核心功能设计

#### 2.2.1 基础行为系统

阿道在桌面上的自主行为（不需要用户触发）：

| 行为 | 触发条件 | 动作描述 | 像素动画 |
|------|---------|---------|---------|
| 巡游 | 每 5-15 分钟随机 | 从屏幕一侧走到另一侧 | walking 帧序列 |
| 趴伏 | 无操作 2 分钟后 | 在屏幕底部或角落趴下 | idle 循环帧 |
| 打盹 | 趴伏超过 5 分钟 | 闭眼、偶尔耳朵动 | sleeping 帧序列 |
| 发呆 | 随机 | 坐着看屏幕边缘、尾巴慢摇 | thinking 变体 |
| 打招呼 | 用户回到电脑（检测鼠标/键盘活动恢复） | 走到中央、冒气泡 "回来了？" | waving |
| 困了 | 23:00-06:00 | 自动进入夜间模式（打盹+Zzz） | 夜间专属帧 |

#### 2.2.2 交互菜单（右键/单击）

```
┌─────────────────────┐
│    🐱 阿道           │
├─────────────────────┤
│  👋 今天运势         │ ← 每日免费一次
│  🔮 排个八字         │ ← 跳转 Web 或内嵌面板
│  🃏 抽张塔罗         │
│  🍖 喂食            │ ← 签到系统
│  💬 聊聊...          │ ← "我今天适合..."
│  ─────────          │
│  👗 换装            │ ← 付费功能
│  📷 截图分享         │ ← 一键生成 SSR 卡
│  ⚙️ 设置            │
└─────────────────────┘
```

#### 2.2.3 命理功能接入方式

**三种方案对比：**

| 方案 | 描述 | 优势 | 劣势 |
|------|------|------|------|
| A: 内嵌 WebView | 桌宠窗口内嵌 Web 页面 | 开发最快、代码复用最高 | 体验割裂（桌宠里套了个网页） |
| B: 原生 UI 重写 | 用 Tauri 原生框架重写命理页面 | 体验一致、像素风统一 | 开发量大、维护两套 UI |
| C: 混合方案 | 桌宠只做轻交互（喂食/聊天/运势），复杂功能跳转浏览器 | 平衡体验和成本 | 用户需要离开桌宠 |

**MVP 推荐：C（混合方案）**
- 桌宠内：喂食 + 每日运势一句话 + 聊天 + 签到
- 点击八字/塔罗等重功能 → 打开默认浏览器访问 cyberfate.me
- V2 再考虑原生内嵌

### 2.4 分发与安装

| 渠道 | 说明 | 优先级 |
|------|------|--------|
| 官网下载页 | cyberfate.me/download | P0 |
| GitHub Releases | 自动更新 + 版本管理 | P0 |
| Steam（远期） | 曝光 + 付费下载/DLC | P2 |
| Homebrew Cask (Mac) | 技术用户渠道 | P1 |
| winget (Windows) | 微软官方包管理器 | P1 |

## 三、手机端桌宠产品设计

### 3.1 四种形态对比

#### 形态 A：桌面 Widget（⭐⭐⭐⭐⭐ 推荐）

| 平台 | 技术方案 | 能力 |
|------|---------|------|
| iOS 17+ | WidgetKit (SwiftUI) | 点击跳转 App、定时刷新内容 |
| Android | App Widget (Jetpack Glance) | 同左 + 部分 Android 支持点击交互 |

**Widget 设计：**

```
┌─────────────────────┐
│  🐱 阿道            │
│                     │
│  "今天宜大胆行动"     │  ← 每日运势一句话
│  大吉 🟢            │
│                     │
│  连续签到 🔥3天      │
│  [喂食]             │  ← 点击跳转 App
└─────────────────────┘
```

- **小尺寸 (SM)**: 阿道头像 + 运势一句话
- **中尺寸 (MD)**: 加上签到按钮 + 连续天数
- **大尺寸 (LG)**: 完整版（阿道立绘 + 运势详情 + 宜忌 Tag）

**这是手机端最重要的形态** — 用户每次亮屏都能看到阿道。

#### 形态 B：App 内常驻（⭐⭐⭐⭐⭐ 必须）

打开 App 就是阿道的"房间"：
- 底部 Tab：首页(阿道房间) / 命理 / 我的
- 首页 = 阿道的空间 + 每日互动入口
- 本质上是 Web 的 App 壳（WebView 或 React Native）

#### 形态 C：推送通知（⭐⭐⭐⭐ 重要）

阿道主动找用户的触达方式：

| 时间 | 推送内容 | 目的 |
|------|---------|------|
| 08:00 | "早安，今日运势已出炉 ☀️" | 日活钩子 |
| 12:00 | "午饭记得吃，本喵饿了 🍖" | 提醒+趣味 |
| 20:00 | "还没看今天的命盘吗？🔮" | 召回流失用户 |
| 特殊日 | "你的星座今日有吉兆 ✨" | 个性化触达 |

**关键原则：每日最多 2-3 条，否则用户关通知 = 死亡。**

#### 形态 D：悬浮窗 / 锁屏（⭐⭐ 可选）

| 平台 | 可行性 | 说明 |
|------|--------|------|
| Android 悬浮窗 | ⭐⭐⭐ | 系统权限敏感，小米/华为限制多 |
| iOS 悬浮窗 | ⭐ | 不支持，PiP 也受限 |
| Android 动态壁纸 | ⭐⭐⭐ | 技术可行但受众窄 |
| iOS 锁屏组件 | ⭐⭐ | Live Activity + WallpaperApp |

**结论：D 类作为 V1.2 远期探索，不做 MVP 承诺。**

### 3.2 手机端技术选型

| 方案 | 技术 | 优势 | 劣势 | 推荐 |
|------|------|------|------|------|
| PWA | Service Worker + Manifest | 一套代码三端运行 | Widget 不支持、推送有限 | MVP 最快路径 |
| React Native | JS/TS | 原生体验 + Widget 支持 | 需要单独维护 | V1 升级目标 |
| Flutter | Dart | 性能好 + 一致性高 | 团队需学 Dart | 如果有 Flutter 经验可选 |
| 原生 (Swift/Kotlin) | 各平台语言 | 最佳体验 | 维护成本高 | 不推荐初期使用 |

**MVP 推荐：PWA + Web App**
- 先用 PWA 覆盖"添加到主屏幕"的基础体验
- 后续升级为 RN/Flutter 做 Widget 和原生推送
- 不要在一开始就做多端 native

## 四、桌宠 vs 纯 Web 方案深度对比

### 4.1 核心指标影响预估

| 指标 | 纯 Web 版 | Web + 桌宠版 | 变化幅度 | 理由 |
|------|----------|-------------|---------|------|
| **DAU/MAU** | 20-25% | **40-55%** | **+100%~+120%** | 桌宠常驻 = 每天自动触达 |
| **次月留存** | 25-35% | **45-60%** | **+20~25ppt** | 沉没成本（装扮/签到记录） |
| **打开频率** | 2-3 次/周 | **7-10 次/周** | **+3-4x** | 每次开电脑/亮屏都看到 |
| **会话时长** | 3-5 分钟 | **1-3 分钟** | 略短 | 桌宠是碎片化互动 |
| **分享率** | 5-20 次/百用户 | **30-60 次/百用户** | **+3x** | 截图/录屏比生成分享卡更自然 |
| **付费转化率** | 2-5% | **4-8%** | **+2x** | 情感连接更深 → 付费意愿更强 |
| **LTV** | ¥200-500 | **¥500-1200** | **+2-2.4x** | 留存延长 + 付费率提升双驱动 |
| **CAC** | ¥10-50 | **¥15-70** | 略高 | 安装成本 > 访问网页 |
| **LTV/CAC** | 4-10x | **7-17x** | **显著改善** | 单位经济模型更健康 |

### 4.2 用户体验地图对比

**纯 Web 版用户一天：**
```
早上 → 忙碌工作，想不起打开
中午 → 可能刷到分享链接 → 打开看看 → 关闭
晚上 → 有空 → 打开查个八字 → 关闭
→ 全天交互 0-2 次
```

**Web + 桌宠版用户一天：**
```
09:00 → 开电脑 → 阿道在桌上打招呼 → 点一下喂食 → ✅ 1次
10:00 → 阿道走到窗口边趴着 → 看一眼觉得可爱 → ✅ 感性触点
12:00 → 手机 Widget 显示"今日大吉" → 点进 App 看运势 → ✅ 2次
14:00 → 阿道挡住了部分窗口 → 拖到角落（互动！） → ✅ 3次
18:00 → 回家路上收到推送"运势已出炉" → ✅ 4次
20:00 → 打开电脑 → 阿道在打盹 → 点一下叫醒 → 查八字 → ✅ 5次
22:00 → 阿道进入夜间模式 → "晚安" → ✅ 6次
→ 全天交互 5-8 次（大部分是无意识的）
```

**关键洞察：桌宠把"我要去用产品"变成了"产品在我身边"。**

### 4.3 获客与分发对比

| 维度 | 纯 Web | 桌宠 |
|------|--------|------|
| 分发门槛 | 点击链接即用 | 需要下载安装 |
| 病毒传播速度 | 快（链接分享） | 慢（需要安装步骤） |
| 传播载体 | SSR 分享卡 | **截图/录屏/GIF（更丰富）** |
| 种子用户转化 | 高（无需安装） | 中（需要说服下载） |
| 长期留存引擎 | 弱（依赖用户记忆） | **强（常驻设备）** |
| 卸载成本 | 无（关闭标签页即可） | **有（沉没成本=留存）** |

## 五、商业影响评估

### 5.1 收入模型变化

**纯 Web 版收入结构（来自 v2 方案）：**
- 会员订阅 70% → 20%
- 广告 20% → 15%
- 装扮/皮肤 0% → 10%

**加入桌宠后的预期变化：**

| 收入来源 | 纯 Web | +桌宠 | 变化原因 |
|---------|--------|-------|---------|
| 会员订阅 | 70% | **55%** | 桌宠本身可以收费（Pro 解锁桌宠功能） |
| 广告 | 20% | **10%** | 桌宠用户付费意愿更高，对广告容忍度更低 |
| 装扮/皮肤 | 0% | **20%** | **桌宠 = 移动的 3D 模型，装扮效果远超 Web 2D** |
| 桌宠 App 售价 | 0% | **10%** | Mac App Store / Microsoft Store 付费下载（¥6-18） |
| 表情包/周边 | 0% | **5% | 桌宠带动 IP 认知 → 衍生品需求 |

**关键新收入来源：桌宠装扮/皮肤**

这是桌宠独有的商业魔法：
- Web 端的装扮只是"换个图标"
- 桌宠端的装扮是**3D 模型/材质实时变化** — 用户愿意为这个付钱
- 参考：VRChat 虚拟形象装扮市场、QQ 秀历史收入

### 5.2 定价调整建议

如果加入桌宠，定价体系需要扩展：

| 版本 | Web 权益 | 新增桌宠权益 | 价格 |
|------|---------|-------------|------|
| 免费 | 基础八字/运势 | 基础桌宠（仅 3 个姿态） | ¥0 |
| Pro | 无限分析 + SSR 卡 | 全部姿态 + Widget + 推送 | ¥18/月 |
| Premium | 全部装扮 + 塔罗全模式 | **独家 3D 装扮 + 动态特效 + 桌宠主题** | ¥38/月 |
| **新增：桌宠买断** | - | 桌宠客户端永久解锁 | **¥28-68 一次性** |

**买断选项的意义：**
- 降低用户心理门槛（"不用订阅也能养猫"）
- 作为获客漏斗（免费桌宠 → 体验后升级 Pro）
- 覆盖不愿意订阅的用户群体

### 5.3 对 M12 目标的影响

| 指标 | 原 v2 目标 (+桌宠后) | 变化 |
|------|---------------------|------|
| MAU | 200,000 | **150,000** | 安装门槛降低总用户数，但质量更高 |
| DAU/MAU | 30% | **45%** | 桌宠常驻驱动日活 |
| 付费转化 | 5% | **7%** | 情感连接加深 |
| MRR | ¥180,000 | **¥220,000** | 新增桌宠买断 + 装扮收入 |
| ARPPU | ¥25 | **¥32** | 装扮消费提升客单价 |
| 次月留存 | 45% | **58%** | 沉没成本效应 |

**结论：总用户数可能略降，但用户质量和 LTV 显著提升。这对小团队来说是更好的商业模式。**

## 七、最终建议

### 7.1 结论：Web 为底 + 桌宠为矛

**不建议完全替代 Web 版。理由：**

1. **获客漏斗不能砍** — Web 版是零门槛入口，用户通过分享链接第一次接触 CyberFate 时应该是网页，不是"请先下载一个 50MB 的安装包"
2. **SEO / 内容营销依赖 Web** — 搜索引擎不索引桌面应用
3. **开发资源不可能同时做三个平台的 MVP** — 必须有优先级

**推荐的渐进式路线：**

```
Phase 1 (Week 1-4): Web 版像素猫改造 MVP
    ↓  验证 PMF：付费转化 >3%、留存 >25%
    
Phase 2 (Month 2-3): PC 桌宠 (Tauri)
    ↓  Pro/Premium 专属功能 + 买断选项
    ↓  验证桌宠留存提升效果
    
Phase 3 (Month 3-4): 移动端升级 (PWA → RN)
    ↓  Widget + 原生推送
    ↓  三端联动的完整体验
```

### 7.2 更新后的优先级矩阵

**MVP（Phase 1）不变 — 先做 Web 版：**

| # | 任务 | 原优先级 | 备注 |
|---|------|---------|------|

**这种社区文化一旦形成，就是极强的护城河。**
