> **文档类型**: 功能改版需求
> **作者**: 产品虾 🦐

> **参考竞品**: FateMaster.AI
> **状态**: 待评审

---

## 一、改版背景

### 1.1 当前问题
经过 FateMaster.AI 竞品分析，发现我们的八字分析页面存在以下问题：

1. **输入体验差**
   - 地点选择用「省份下拉菜单」，交互成本高
   - 阳历/农历切换用下拉菜单，不够直观
   - 缺少「不知道出生时间」的场景支持

2. **转化率低**
   - 页面只有表单，缺少产品价值说明
   - 用户不知道「为什么要填」「会得到什么」
   - 没有引导探索其他功能

3. **专业度不足**
   - 缺少早晚子时处理（专业用户需求）
   - 没有知识库/理论支撑
   - 功能单一，看不到产品深度

### 1.2 竞品优势（FateMaster.AI）
- ✅ 单页全流程：输入 + 介绍 + FAQ 一页搞定
- ✅ 地点搜索框：输入「北京」自动匹配，省力
- ✅ 出生时间开关：照顾不知道时辰的用户
- ✅ 早晚子时开关：专业功能
- ✅ 功能矩阵展示：9+ 场景（合婚、事业、婆媳等）
- ✅ 知识库入口：天干地支、神煞理论等

---

## 二、改版目标

### 2.1 用户体验目标
- 降低输入门槛，提升表单填写完成率 **+30%**
- 提升首次访问用户的「立即计算」转化率 **+40%**
- 增强专业形象，吸引深度用户

### 2.2 商业目标
- 提升从免费用户到 VIP 的转化率 **+20%**
- 增加页面停留时长 **+50%**（通过知识内容）
- 为后续功能矩阵（合婚、事业等）铺路

## 三、改版需求（按优先级）

### 3.1 P0 - 核心体验优化

#### **需求 0：新增侧边栏导航**

**当前问题**：
- 桌面端顶部导航占用空间，信息密度低
- 功能入口不够直观，用户需要展开菜单才能看到所有功能
- 缺少「工作空间」概念，像工具集而非产品

**改版方案**：
- 学习 FateMaster，增加 **侧边栏导航**（桌面端 + 平板横屏）
- 移动端保持顶部导航（屏幕窄，侧边栏会挤压内容区）

**侧边栏结构**（参考 FateMaster）：
```
┌─────────────────┐
│ CyberFate Logo  │
├─────────────────┤
│ 八字解命        │
│  • 八字计算     │
│  • 八字合婚     │
│  • 每日运势     │
├─────────────────┤
│ 紫微斗数        │
│  • 紫微排盘     │
├─────────────────┤
│ 周易占卜        │
│  • 梅花易数     │
│  • 六爻         │
├─────────────────┤
│ 塔罗牌          │
│  • 塔罗占卜     │
├─────────────────┤
│ 其他功能        │
│  • AI 老黄历    │
├─────────────────┤
│ [用户头像]      │
│  个人资料       │
│  退出登录       │
└─────────────────┘
```

**视觉设计**：
- 宽度：240px（桌面端）
- 背景：浅灰/白色（保持 CyberFate 简约风格，不用 FateMaster 的深色）
- 当前页面高亮显示（黑底白字或加粗）
- 图标 + 文字（图标统一风格）
- 可折叠（点击 Logo 旁边的折叠按钮，只显示图标）

**响应式适配**：
- **≥1024px**（桌面/平板横屏）：显示侧边栏
- **<1024px**（平板竖屏/手机）：隐藏侧边栏，顶部显示汉堡菜单
- 汉堡菜单点开后，从左侧滑出抽屉式导航

**交互细节**：
- 分组标题（八字解命、紫微斗数等）可折叠/展开
- 子功能悬停时显示简短描述（Tooltip）
- 当前页面所在分组默认展开

**技术实现**：
- 使用 Next.js App Router Layout
- 侧边栏组件：`<Sidebar />`，放在 `app/layout.tsx`
- 状态管理：用户展开/折叠偏好存 localStorage

**验收标准**：
- [ ] 桌面端侧边栏正常显示
- [ ] 移动端自动隐藏，汉堡菜单可用
- [ ] 当前页面高亮显示
- [ ] 分组折叠/展开交互流畅
- [ ] 折叠侧边栏后内容区自动扩宽

#### **需求 1：地点输入改为搜索框**

**当前问题**：
- 省份下拉菜单 → 用户需要点 2 次（省份 + 城市）
- 体验繁琐，容易放弃

**改版方案**：
- 改为**搜索框**，输入「北京」「上海」「深圳」自动匹配
- 支持模糊搜索（拼音、简称）
- 后端返回 `{city: "北京市", province: "北京", timezone: "UTC+8"}`

**技术实现**：
- 前端：使用 `<input>` + autocomplete 组件
- 后端：城市数据库（含拼音索引）
- API：`GET /api/cities?q=北京` 返回候选列表

**验收标准**：
- [ ] 输入「北京」能匹配到「北京市」
- [ ] 输入「bj」能模糊匹配到「北京」
- [ ] 选择后自动填充完整地名
- [ ] 移动端体验流畅（虚拟键盘不遮挡候选列表）

---

#### **需求 2：阳历/农历改为 Tab 切换**

**当前问题**：
- 下拉菜单交互成本高，视觉不够突出

**改版方案**：
- 改为 **Tab 按钮**（类似 FateMaster）
- 默认选中「阳历」
- 切换后日期选择器逻辑自动切换

**设计稿**：
```
┌─────────────────────┐
│ [阳历] [农历]       │  ← Tab 按钮
│ 2026年04月01日      │  ← 日期选择器
└─────────────────────┘
```

**验收标准**：
- [ ] Tab 按钮视觉清晰（选中态有明显区分）
- [ ] 切换时日期选择器逻辑切换（阳历 ↔ 农历）
- [ ] 移动端点击区域足够大（44px × 44px）

#### **需求 3：新增「我知道出生时间」开关**

**当前问题**：
- 强制用户选择出生时间，但很多人不知道准确时辰
- 不知道的人随便选 → 结果不准 → 不信任产品

**改版方案**：
- 新增 **Switch 开关**「我知道出生时间」
- 默认状态：**开启**（显示时间选择器）
- 关闭后：时间选择器隐藏，提示「将为您提供全天时辰综合分析」

**后端逻辑**：
- 关闭时：后端按 12 个时辰全部计算，返回「综合特征」或「可能性最高的 3 个时辰分析」
- 或引导用户：「根据性格特征反推时辰」（高级功能）

**设计稿**：
```
┌─────────────────────────────────┐
│ 我知道出生时间  [ON]            │  ← Switch 开关
│                                  │
│ ┌───────────────┐                │  ← 时间选择器
│ │ 16 时 03 分   │                │
│ └───────────────┘                │
└─────────────────────────────────┘

关闭后：
┌─────────────────────────────────┐
│ 我知道出生时间  [OFF]           │
│                                  │
│ 💡 将为您提供全天时辰综合分析   │
└─────────────────────────────────┘
```

**验收标准**：
- [ ] 开关默认开启
- [ ] 关闭后时间选择器隐藏
- [ ] 提示文案清晰
- [ ] 后端能处理「无时辰」请求

### 3.2 P1 - 转化率优化

#### **需求 4：单页设计 + 产品介绍前置**

**当前问题**：
- 页面只有表单，用户不知道「填了有什么用」
- 没有信任背书，没有价值传递

**改版方案**：
- 在表单下方增加 **4 个板块**：

**板块 1：AI 智能八字解析系统**（4 个卖点）
- 精准命盘
- AI 解读
- 科学客观
- 全方位分析

**板块 2：全方位命理解析**（4 个维度）
- 性格洞察
- 事业方向
- 财运特征
- 健康运势

**板块 3：使用指南**（4 步流程）
1. 填写出生信息
2. 选择性别
3. 确认历法
4. 获取分析报告

**板块 4：常见问题 FAQ**
- 八字分析准确吗？
- 不知道准确出生时间怎么办？
- 八字和西方星座有什么区别？
- 多久查看一次八字分析？
- 八字能帮助做重要决定吗？

**视觉风格**：
- 保持 CyberFate 黑白极简风格
- 用图标 + 简短文案（不要长篇大论）
- 参考 FateMaster 的信息密度，但不照抄

**验收标准**：
- [ ] 4 个板块内容完整
- [ ] 排版清晰，不拥挤
- [ ] 移动端适配良好
- [ ] FAQ 可折叠/展开

---

#### **需求 5：新增「早晚子时」开关**

**当前问题**：
- 缺少专业功能，无法满足深度用户需求
- 子时出生的人（23:00-01:00）计日方式有争议

**改版方案**：
- 新增 **Switch 开关**「使用早晚子时」
- 默认状态：**关闭**（按传统方式，23:00 后算次日）
- 开启后：23:00-24:00 算前一天，00:00-01:00 算当天

**提示文案**：
- 开关下方加说明：「早子时（23:00-24:00）归前一日，晚子时（00:00-01:00）归当日」

**验收标准**：
- [ ] 开关默认关闭
- [ ] 开启后日期计算逻辑正确
- [ ] 提示文案清晰易懂

#### **需求 6：功能矩阵展示**

- 点击跳转到对应页面

**验收标准**：
- [ ] 功能矩阵清晰展示
- [ ] 点击跳转正确
- [ ] 移动端横向滑动体验流畅

### 3.3 P2 - 专业度提升

#### **需求 7：知识库入口**

**当前问题**：
- 缺少理论支撑，无法建立专业形象
- SEO 权重低，缺少长尾关键词

**改版方案**：
- Footer 增加「理论知识」板块
- 包含：
  - 五行理论
  - 十天干理论
  - 十二地支理论
  - 神煞大全
  - 八字格局
  - 刑冲会合法则
  - 大运理论
  - 真太阳时理论
  - 早晚子时理论

**实现方式**：
- 每个理论对应一个独立页面（Markdown 生成）
- 内容由 AI 生成 + 人工审核
- 页面结构：标题 + 释义 + 举例 + 相关理论链接

**验收标准**：
- [ ] Footer 有理论知识入口
- [ ] 每个理论页面内容完整
- [ ] SEO 优化（meta 标签、关键词）

#### **需求 8：历史记录功能**

**当前问题**：
- 用户每次都要重新输入信息
- 无法对比不同时间的分析结果

**改版方案**：
- 个人中心增加「历史记录」tab
- 展示：
  - 姓名
  - 出生信息（年月日时 + 地点）
  - 计算时间
  - 快速重新分析按钮
- 支持删除历史记录

**技术实现**：
- 数据库表：`bazi_records`
- 字段：`user_id`, `name`, `birth_info`, `created_at`
- 需要登录态

**验收标准**：
- [ ] 登录用户自动保存历史记录
- [ ] 历史记录页面清晰展示
- [ ] 点击「重新分析」能快速填充表单

## 四、设计规范

### 4.1 视觉风格
- 保持 CyberFate 黑白极简风格
- 不照搬 FateMaster 的柔和紫/蓝配色
- 强调「赛博」「现代」「理性」

### 4.2 交互原则
- 表单输入：减少点击次数，优先自动补全
- 开关按钮：状态明确，提示清晰
- 信息展示：图标 + 简短文案，避免长篇文字

### 4.3 移动端适配
- 所有按钮点击区域 ≥ 44px × 44px
- 搜索框虚拟键盘不遮挡候选列表
- Tab 切换按钮大小适中

## 七、风险与应对

### 7.1 技术风险
**风险**：地点搜索框性能问题（城市数据量大）
**应对**：
- 使用防抖（debounce）减少请求
- 后端缓存常用城市
- 候选列表限制 10 条

### 7.2 用户教育风险
**风险**：「早晚子时」「无时辰分析」用户不理解
**应对**：
- 提示文案简洁明了
- FAQ 中解释清楚
- 提供「了解更多」链接

### 7.3 开发排期风险
**风险**：P2 知识库内容生成量大，可能延期
**应对**：
- 优先上线 P0 + P1
- P2 分批上线（先上 5 个核心理论，后续逐步补充）
