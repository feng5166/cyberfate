## 三、订阅计划成本模型

### 3.1 各档计划参数

| 维度 | Daily (¥9.9) | Yearly (¥49.9) | Lifetime (¥198) |
|------|-------------|---------------|----------------|
| 授权时长 | 1 天 | 365 天 | 永久（按 100 年建模） |
| 八字分析次数/天 | 3 | 无限 | 无限 |
| 塔罗次数/天 | 6（3+3） | 无限 | 无限 |
| 预估 AI 调用/天 | 9 | 5–20 | 5–50 |
| 单日 AI 成本（估算） | ¥0.03–0.08 | ¥0.02–0.10 | ¥0.02–0.15 |
| **期间总 AI 成本** | **¥0.03–0.08** | **¥7–36** | **¥73–5475** |
| **AI 成本/收入比** | **0.3–0.8%** ✅ | **14–72%** ⚠️ | **37%–2765%** 🔴 |

> Lifetime 建模说明：保守取 10 年活跃使用（而非 100 年），AI 成本 = 10 × 365 × avg_cost。  
> 即使只活跃使用 **5 年**，重度用户（20 calls/day × ¥0.005 × 5 × 365 = ¥182.5）已接近收入上限。

### 3.2 Lifetime 亏损临界点分析 🔴

```
收入：¥198（一次性）
损益平衡调用量 = ¥198 / ¥0.004(avg) = 49,500 次 AI 调用
等价于：每天 5 次调用 × 27 年 = 亏损临界
         每天 20 次调用 × 7 年 = 亏损临界
         每天 50 次调用 × 2.7 年 = 亏损临界

结论：Lifetime 计划在 3–7 年内对活跃用户几乎必然亏损。
```

### 3.3 风险建议

| 风险等级 | 建议 |
|---------|------|
| 🔴 Lifetime | 立即评估是否继续销售；若保留须增加限制（每日调用上限/功能限额）|
| ⚠️ Yearly | 提升缓存命中率，目标将实际 AI 成本压到 ¥15 以内（<30% 毛利损耗）|
| ✅ Daily | 成本结构健康，维持现状 |

## 四、Prompt 优化分析（src/lib/ai/prompts.ts）

### 4.1 各 System Prompt 字符统计

| Prompt | 字符数（含 SAFETY_GUARDRAIL） | 估算 tokens | 可优化潜力 |
|--------|--------------------------|-----------|---------|
| `SAFETY_GUARDRAIL`（共享） | ~450 字符 | ~225–300 | 低（合规必需） |
| `BAZI_SYSTEM_PROMPT` | ~2,200 字符 | **~1,100–1,470** | 高 ⚠️ |
| `DAILY_SYSTEM_PROMPT` | ~1,150 字符 | ~575–767 | 中 |
| `buildTarotReadingSystemPrompt`（three） | ~1,400 字符 | ~700–933 | 中 |
| `MEIHUA_DECISION_SYSTEM_PROMPT` | ~1,800 字符 | ~900–1,200 | 中 |
| `LIUYAO_SYSTEM_PROMPT` | ~2,100 字符 | **~1,050–1,400** | 高 ⚠️ |

> 注：中文文本 tokenization 约 1.5–2 字符/token（具体取决于模型）。

### 4.2 可精简内容识别

**BAZI_SYSTEM_PROMPT（最大，最优先优化）**

目前包含完整 Few-shot 示例（约 800 字符 / ~400–530 tokens）：

```
当前：系统 prompt ~1,100–1,470 tokens（含 Few-shot 示例）
目标：~770–1,030 tokens（精简 30%）
```

可精简方向：
- Few-shot 示例中的各字段可从 5–6 句话压缩到 3–4 句（约节省 200 字符）
- 字数要求说明可合并为一行（如"各字段字数见字段注释"）
- 移除冗余的"不得少于 XXX 字"重复说明（已在每个字段后重复）

**LIUYAO_SYSTEM_PROMPT（第二大）**

六亲推演框架 5 条展开详细，可压缩：

```
当前：~1,050–1,400 tokens
目标：~735–980 tokens（精简 30%）
```

可精简方向：
- 六亲推演 5 条规则可缩写 50%（保留要点，删除举例说明）
- 输出格式示例可改为 schema 描述，不必写完整 JSON

**SAFETY_GUARDRAIL（所有 prompt 共用）**

目前约 450 字符，每次调用都会包含：
- 4 条安全禁区
- 4 条内容规范

优化方案：将 SAFETY_GUARDRAIL 注册为 Prompt Caching 锚点（见第五章）。

### 4.3 Prompt 压缩目标（30% 减少 token）

| Prompt | 当前估算 tokens | 目标 tokens | 节省金额/次（估算） |
|--------|--------------|------------|-----------------|
| 八字系统 prompt | 1,285 | 900 | ¥0.000385 |
| 六爻系统 prompt | 1,225 | 858 | ¥0.000367 |
| 塔罗系统 prompt | 817 | 572 | ¥0.000245 |
| 梅花系统 prompt | 1,050 | 735 | ¥0.000315 |

> 若每日 1,000 次高峰调用，全量压缩可节省约 ¥0.35/天 → 约 ¥130/年。

## 五、缓存成本效益分析

### 5.1 当前缓存状态

| 功能 | 缓存策略 | 缓存 Key | 评价 |
|------|---------|---------|------|
| 八字分析 | Redis 永久缓存 | `v4:bazi:{sha256(date+hour+gender)}` | ✅ 极佳：同一用户终生只调 1 次 AI |
| 每日运势 | Redis 24h TTL | `daily:{dayMaster}:{dayun}:{liunian}:{date}` | ✅ 良好：每用户每天 1 次 AI |
| 塔罗解读 | **无缓存** | — | ⚠️ 每次都调 AI |
| 梅花易数 | **无缓存** | — | ⚠️ 每次都调 AI |
| 六爻占卜 | **无缓存** | — | ⚠️ 每次都调 AI |
| 黄历问事 | 未知 | — | ❓ 需确认 |

### 5.2 建议为塔罗/梅花/六爻添加缓存

塔罗：相同牌阵（相同牌 + 相同问题 hash）的解读可共享

```typescript
// 建议 key 格式
const tarotCacheKey = `tarot:${spread}:${hashCards(cards)}:${hashQuestion(question)}`;
// TTL：6小时（避免用户在同一天重复抽同一牌阵）
await redis.setex(tarotCacheKey, 21600, result);
```

梅花/六爻：相同卦象结构 + 相同问题可共享结果

```typescript
// 梅花 key
const meihuaKey = `meihua:${guaName}:${changedGuaName}:${movingLine}:${hashQuestion(question)}`;
// TTL：1小时（问题时效性较强）
```

### 5.3 缓存提升预期成本节省

假设高峰日 1,000 次调用：

| 场景 | 无缓存成本 | 预期命中率 | 缓存后成本 | 节省 |
|------|----------|---------|----------|------|
| 八字（现有缓存） | ¥4.8 | ~85% | ¥0.72 | ¥4.08 |
| 每日运势（现有缓存） | ¥1.6 | ~70% | ¥0.48 | ¥1.12 |
| 塔罗（无缓存） | ¥3.0 | 0% → **30%** | ¥2.10 | **¥0.90** |
| 梅花（无缓存） | ¥1.9 | 0% → **20%** | ¥1.52 | **¥0.38** |
| 六爻（无缓存） | ¥3.1 | 0% → **20%** | ¥2.48 | **¥0.62** |

> 添加塔罗/梅花/六爻缓存后，每日可节省约 ¥1.90，年化 ¥693。

### 5.4 Prompt Caching 优化（长期方案）

DeepSeek 若支持 Prompt Caching（类似 Anthropic API），SAFETY_GUARDRAIL（~300 tokens）作为所有 prompt 的公共前缀，可享受缓存折扣：

- 当前每次调用都发送完整 SAFETY_GUARDRAIL
- 若缓存命中率 80%，SAFETY_GUARDRAIL 成本降低 80%
- 年化节省（1,000 调用/天 × ¥0.0003 × 0.8 × 365）≈ ¥87.6

## 六、LTV / CAC 模型

### 6.1 基础假设

| 参数 | 值 | 来源/假设 |
|------|----|---------| 
| CAC（获客成本） | ¥15–50 | 中文命理市场 SEO + 社交推广估算 |
| Daily 平均留存 | 1.2 天 | 假设 20% 次日复购 |
| Yearly 平均活跃天数 | 180 天/年 | 含季节性波动 |
| Yearly 续费率 | 60% | 同类 SaaS 参考 |
| Lifetime 一次性 | — | 无续费 |
| 毛利率（扣除 AI 成本） | 28–86% | 按 AI 成本占比反推 |

### 6.2 各档 LTV 计算

**Daily 计划（¥9.9/天）**

```
首次收入：      ¥9.9
AI 成本：       ¥0.05（中位数）
毛利：          ¥9.85（~99%）
复购（20%）：  ¥9.9 × 0.2 = ¥1.98 附加 LTV
LTV（估算）：   ¥11.9
CAC：           ¥15–50
LTV/CAC：       0.24–0.79 ❌ 低于 1，获客不合算！
回收周期：      需 1.3–4.2 次购买（约 1.6–5 天）
```

> ⚠️ Daily 计划 LTV/CAC < 1 意味着靠单次 daily 用户无法回收获客成本。需提升 Daily → Yearly 的转化率。

**Yearly 计划（¥49.9/年，60% 续费）**

```
年 1 收入：     ¥49.9
AI 成本（年）：  ¥14–36
年 1 毛利：     ¥13.9–35.9

LTV（几何级数，60% 续费）：
  = ¥49.9 / (1 - 0.6) = ¥124.75（收入端）
  
扣除各年 AI 成本（平均 ¥25/年）：
  AI 总成本 = ¥25 × (1 + 0.6 + 0.36 + ...) = ¥25 / 0.4 = ¥62.5
  净 LTV = ¥124.75 - ¥62.5 = ¥62.25

CAC：           ¥15–50
LTV/CAC：       1.25–4.15 ✅
回收周期：      3–12 个月（健康区间：<12 个月）
```

**Lifetime 计划（¥198 一次性）**

```
收入：          ¥198（全部）
预期 AI 成本：
  保守用户（5 calls/day × 5年）：¥0.003 × 5 × 365 × 5 = ¥27.4
  普通用户（10 calls/day × 5年）：¥54.8
  重度用户（20 calls/day × 5年）：¥109.5
  超重度（50 calls/day × 10年）：¥547.5

净利润：
  保守：+¥170.6  ✅
  普通：+¥143.2  ✅
  重度：+¥88.5   ✅（尚可）
  超重度：-¥349.5 🔴 严重亏损！

期望 LTV（考虑用户分布混合）：
  假设 80% 普通 + 15% 重度 + 5% 超重度
  加权 AI 成本 = 0.8×54.8 + 0.15×109.5 + 0.05×547.5 = 43.84+16.43+27.38 = ¥87.6
  期望净利润 = ¥198 - ¥87.6 = ¥110.4

CAC：           ¥15–50
LTV/CAC（期望）：2.2–7.4 ✅（表面看起来健康）
真实风险：超重度用户（5%）每人亏损 ¥350+，可能拖垮整体利润
```

### 6.3 总结矩阵

| 计划 | LTV | LTV/CAC | 回收周期 | 风险等级 | 建议 |
|------|-----|---------|---------|---------|------|
| Daily ¥9.9 | ¥11.9 | 0.24–0.79 | — | 🔴 亏损 | 提升转化为 Yearly |
| Yearly ¥49.9 | ¥62.3 | 1.25–4.15 | 3–12 月 | ✅ 健康 | 主推计划 |
| Lifetime ¥198 | ¥110.4（期望） | 2.2–7.4 | 立即回收 | ⚠️ 重度用户风险 | 限流保护 |

## 附录：关键公式

```
单次调用成本 = (输入tokens × 0.001 + 输出tokens × 0.002) / 1000  [单位：¥，估算]
年化 AI 成本 = 日均调用次数 × 平均单次成本 × 365
LTV = 年收入 / (1 - 续费率)  [几何级数公式]
LTV/CAC 健康标准：> 3（理想），> 1（最低可接受）
Lifetime 临界点 = 收入 / 平均单次 AI 成本 = ¥198 / ¥0.004 = 49,500 次调用
```
