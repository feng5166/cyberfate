# 塔罗占卜 V2 · 产品需求文档

> 基线:2026-08-01 main 分支现状(V1 已上线:78 张全牌库 + 6 牌阵(凯尔特 VIP)+ 两段式 API(抽牌/解读分离)+ 反注入可信牌库校正 + 结构化 prompt 工程 + 打字机流式 + 配额退还 + VIP 历史持久化)。
> V2 主题:**把「抽卡结果页」变成「一场有仪式感的占卜」——塔罗卖的从来不是答案,是翻牌那一刻的心跳。**
> 配套阅读:`PRD-BAZI-V2.md` / `PRD-ZIWEI-V2.md`(追问/分享/漏斗方法论同源)、`DESIGN-SYSTEM.md`(塔罗模块色 `#E0E7FF` / `#4338CA`)。

## 1. 背景与诊断

### 1.1 资产盘点(V1 好的部分,全站前列)

- **牌库完整**:78 张韦特全牌(大阿卡纳+四花色),正逆牌义+关键词+牌图俱全——**全站最强视觉资产**。
- **工程链路成熟**:两段式 API(先抽牌后解读,天然支持仪式化前端);服务端可信牌库反查(杜绝伪造牌义/prompt 注入);原子配额+AI 失败退还;12h 缓存;VIP 历史已持久化。
- **prompt 工程全站最精**:分牌阵叙事结构、逆位三态原则(受阻/过剩/内化)、元素互动与数字重复规则——解读质量底子好。

### 1.2 八个结构性问题(按对「受欢迎程度」的影响排序)

| # | 问题 | 证据 |
|---|------|------|
| R1 | **仪式感为零**:点按钮 → 转圈 → 牌直接正面躺出来。没有洗牌、没有牌背、没有「自己翻牌」——塔罗的心理内核(参与感与掌控感)完全缺席,像抽奖不像占卜 | PageClient `step==='drawing'` 只有 OracleLoading;`drawn` 直接展示正面牌图 |
| R2 | **占卜后不能追问**:用户抽完牌满脑子「那我该怎么办」「对方到底怎么想」,页面到此为止。全站成熟问答设施(chat 组件+三层门禁+事实注入)塔罗没接——八字 V2 已验证这是漏斗断层 | 无 `/api/tarot/chat` |
| R3 | **分享是纯文本**:navigator.share 一段文字。78 张牌图闲置,没有牌阵分享卡图——塔罗牌面是全站最适合发朋友圈的素材 | `api/tarot/share` 仅拼 shareText |
| R4 | **零回访钩子**:没有「每日一牌」;历史记录 API 存在但页面无入口,且 VIP 专属,免费用户抽完即忘 | history/route.ts VIP-only;PageClient 无历史 UI |
| R5 | **问题与牌阵脱节**:5 种牌阵靠用户自己猜着选;感情问题选了「经典」、决策问题选了「月光」没人纠正。塔罗师的第一件事——把模糊问题变成好问题——产品没做 | MODES 平铺,无推荐逻辑 |
| R6 | **解读无「一句话答案」置顶**:prompt 有开篇定调,但 UI 是整篇文章流,先看到的是铺垫;移动端读完全文的比例可想而知。行动建议也埋在文末,没被提炼成可勾选的清单 | 结果区 `reading` 全文渲染 |
| R7 | **漏斗埋点粗**:仅 tool_submit / tool_result_view 两个事件,抽牌→翻牌→解读→追问→分享全链路盲 | PageClient 全文 |
| R8 | **变现中间层薄**:免费=单张1+进阶1/日,VIP=凯尔特+不限。中间没有尝鲜层(追问/历史/深挖),从免费到 $49/年之间没有台阶 | quota 现状 |

**一句话诊断:V1 是一台解读质量不错的「塔罗自动售货机」——投币出货,但塔罗用户要的是一场occasion(仪式),不是一次 vending(售卖)。**

### 1.3 用户视角(塔罗师判断)

塔罗与八字/紫微的用户心智完全不同:
1. **八字看命,塔罗问事**——高频、短决策、情绪驱动,天然适合日活;
2. **仪式即产品**:洗牌-切牌-翻牌的过程产生「这是我的牌」的心理所有权,直接决定信任度与分享率;
3. **翻牌瞬间是情绪峰值**:峰终定律——把体验设计压在「翻牌」与「一句话答案」两个点上;
4. **追问是天性**:一次占卜平均引出 2-3 个衍生问题,不接住就流失。

## 2. 目标与非目标

**目标**(按优先序):
1. **仪式感重构**:洗牌动画 → 牌背扇排 → 用户逐张翻牌,零后端改动(两段式 API 现成)。
2. **翻牌后的情绪峰值承接**:「一句话答案」置顶 + 行动清单提炼。
3. **追问闭环**:免费 1 次/日,先尝后买(方法论同八字 P1-A)。
4. **牌阵分享卡**:牌图 + 一句话答案合成图片,吃透视觉资产红利。
5. **回访钩子**:每日一牌(确定性零 AI 成本)+ 历史入口分层开放。

**非目标**:
- 不动解读 prompt 主体结构(质量已好,只加「一句话答案」字段);
- 不做真人塔罗师连线、不做付费单次解锁(维持订阅制);
- 不做自定义牌阵编辑器(V3+);
- 伦理红线:不回答医疗/法律/怀孕/寿命类问题(SAFETY_GUARDRAIL 已有,追问沿用),不用「厄运」话术制造焦虑后卖解读。

**北极星指标**:翻牌完成率(抽牌成功 → 全部翻开)× 解读生成率。护栏:增加翻牌步骤后「抽牌→解读」转化不得低于现基线(提供「一键全部翻开」逃生门)。

## 3. 功能设计

### P0-A 仪式感三部曲(纯前端,零后端改动)

抽牌流程从「转圈→结果」改为:
1. **洗牌**(1.5-2s):牌堆洗切 CSS 动画(牌背交叠飞舞,`prefers-reduced-motion` 直接跳过);
2. **牌背亮相**:按牌阵位形摆出 N 张**牌背**(新增统一牌背图,现缺此资产——用模块色 #4338CA 细线纹样绘制,风格遵循设计系统装饰语言);
3. **逐张翻牌**:点击翻转(3D flip,翻开即显示牌名+正逆位标签);全部翻完自动滚动至「AI 解读牌义」按钮并高亮。**顶部提供「一键全部翻开」**(护栏逃生门,埋点区分)。
- 两段式 API 现成:`draw-cards` 返回后先渲染牌背,牌面数据已在客户端,翻牌零延迟。
- **埋点**:`tarot_shuffle_done` / `tarot_flip_card {index}` / `tarot_flip_all_click` / `tarot_flip_complete`。

### P0-B 一句话答案 + 行动清单(峰值承接)

- prompt 输出 JSON 增加两个字段:`oneLineAnswer`(≤40 字,直接回答用户的问题)、`actions`(1-3 条可执行建议数组)。兜底:字段缺失时前端不渲染该区块,全文流不受影响(向后兼容旧缓存)。
- 结果页结构:**一句话答案卡置顶**(模块色描边,可单独复制)→ 牌阵图 → 全文解读 → **行动清单**(checkbox 样式,纯展示)→ 追问入口。
- **埋点**:`tarot_answer_view` / `tarot_reading_done`(全文滚动到底)。

### P0-C 追问免费 1 次/日(转化中间层)

- 新 `/api/tarot/chat`:事实注入 = 本次牌阵(牌名/正逆/牌位/牌义)+ 原问题 + AI 解读摘要;三层门禁(未登录 401 → 免费 `tarotChatCount` 1 次/日(迁移 009)→ VIP 不限);SAFETY_GUARDRAIL 沿用;回答尾部非 VIP 追加升级引导(streamProxy `suffixFrames` 现成)。
- 前端复用 BaziChatSection 交互模式(预设问题:「那我该怎么做?」「对方是什么态度?」「什么时候会有变化?」)。
- **埋点**:`tarot_chat_try {is_vip}` / `tarot_chat_paywall_show`。

### P1-A 牌阵分享卡(视觉资产变现)

- canvas 合成 750×1334:牌阵布局牌图(1/3/5 张;凯尔特取关键 4 张)+ 问题(用户可选是否带上)+ 一句话答案 + 二维码(`/tarot?ref=share`)+ 免责行。牌图即吸睛点,不需要花哨排版。
- 现纯文本分享保留为次选项;分享卡为主按钮。
- **埋点**:`tarot_share_open` / `tarot_share_export {mode}`。

### P1-B 每日一牌(回访钩子,零 AI 成本)

- 每人每天一张固定牌:`hash(userId|游客指纹, 北京日期)` 确定性抽取(同一天刷新不变)——「今天的牌」有仪式正当性;
- 卡面:牌图 + 正逆位 + 今日主题词 + 一句白话(牌义模板拼接,零 AI)+ 「想深挖这张牌对你今天的意义?」→ 单张牌阵入口(走现有配额);
- 位置:塔罗页顶部横幅卡 + 首页可后续引流;
- **埋点**:`tarot_daily_card_view` / `tarot_daily_card_flip` / `tarot_daily_to_reading`。

### P1-C 问题引导 + 牌阵推荐(塔罗师的第一课)

- 输入问题后关键词轻量分类(感情/事业财务/自我成长/是非决策),对应牌阵卡打「适合这个问题」徽标(关系牌阵←感情双人;镜像←复杂决策;月光←情绪内省;经典←通用);纯前端规则,零 AI。
- 「好问题」引导:检测「会不会/能不能+第三人称」类封闭问题时,输入框下方温和提示示例改写(「把『他还爱我吗』换成『我在这段关系里该把注意力放在哪』,牌会给你更有用的答案」)——塔罗伦理即产品口碑。
- **埋点**:`tarot_spread_recommend_show {spread}` / `tarot_spread_recommend_follow`。

### P1-D 历史入口分层开放

- 历史 API 从 VIP-only 改为:**免费登录可看最近 3 条,VIP 全部**(服务端分层,列表尾部锁定占位 + 升级 CTA);
- 塔罗页顶部「我的占卜」入口(登录后显示);抽新牌前展示上次占卜的一句话答案(「上次你问了…,这次想问什么?」——连续感)。
- **埋点**:`tarot_history_open` / `tarot_history_paywall_click`。

### P2 收尾三件

- **P2-A 大阿卡纳时刻**:翻出大阿卡纳时卡面微光效 + 一行牌语(「Death 不是终结,是腾位置给新生」)——教育性文案化解「凶牌」恐惧,22 条模板;埋点 `tarot_major_moment`。
- **P2-B 逆位开关**:高级选项「本次不用逆位」(新手/柔和模式;抽牌参数 `noReversal`,draw-cards/draw 各加一个透传布尔);
- **P2-C 牌义百科锚点**:牌义弹窗底部「了解这张牌的完整故事」→ 知识库塔罗词条(如无则先占位到 `/knowledge`)。

## 6. 里程碑

| 阶段 | 内容 | 验收口径 |
|------|------|----------|
| M1(仪式与峰值) | P0-A 翻牌三部曲、P0-B 一句话答案/行动清单、埋点全链路 | 翻牌完成率基线;抽牌→解读转化不低于旧基线 |

## 7. 风险与表述规范

1. **仪式步骤增加流失**:翻牌是多出来的一步——「一键全部翻开」常驻 + 洗牌动画尊重 reduced-motion + 总时长控制(洗牌≤2s);上线后盯抽牌→解读转化,若降超 5% 则默认改为「自动连翻动画」保留观感、去掉点击成本(改常量级)。
2. **每日一牌的确定性**:游客指纹用 localStorage 随机 ID(非设备指纹,避免隐私争议);换设备牌不同属可接受口径。
3. **表述规范**:逆位/「凶牌」一律走既有 SAFETY_GUARDRAIL + 大阿卡纳教育文案;追问不回答医疗/法律/生死类问题;禁用恐吓话术导流付费。
4. **分享隐私**:分享卡默认不带问题原文(用户勾选才带),防止敏感问题外泄。
