> 基线:2026-08-01 main 分支现状(V1 已上线:三合派真实排盘引擎 + 4×4 宫格/移动列表 + 宫位详情 + 星曜字典 + 分享截图)。
> V2 主题:**下线全部假 AI 内容,把命盘变成「可以逐宫追问的人生地图」——排盘引擎是真的,解读层从零建,方法论全部复用八字 V2。**
> 配套阅读:`PRD-BAZI-V2.md`(议题式方法论同源)、`PRD-LIFE-KLINE-V2.md`、`DESIGN-SYSTEM.md`(紫微模块色 `#F3E8FF` / `#7E22CE`)。

## 1. 背景与诊断

### 1.1 资产盘点(V1 好的部分)

- **排盘引擎真实且有测试**:三合派 14 主星 + 辅煞星 + 生年四化 + 庙旺陷亮度,`calculator.test.ts` 302 行覆盖。
- **命盘 UI 是全站最好的可视化底子**:桌面 4×4 田字格 + 中宫信息卡、移动端列表、宫位点选详情、星曜字典(408 行真实词条)、四化飞星动画。
- 输入表单简洁,统一门禁(`useAiGate`)已接。

### 1.2 七个结构性问题(按严重度排序)

| # | 问题 | 证据 |
|---|------|------|
| Z1 | **「AI 命盘解读」是写死的假文案**:三个 tab(总览/四化/大运)全部是「紫府同宫上格」样板文,与用户真实命盘无关——武曲坐命的用户也被告知自己紫府同宫 | `ZiweiAiOverview.tsx` L89-127 `STATIC_TAB_CONTENT`,仅一枚小小「示例」角标 |
| Z2 | **大运流年是假算法**:固定 3 岁起运、每运 10 年、宫位描述硬编码轮播;紫微真实大限须由五行局起限岁数 + 阴阳男女顺逆行——引擎已算出 `wuxingJuNumber` 却从未使用 | `DayunSwitcher.tsx` L30-56、`lib/utils/dayun.ts` `STARTING_AGE=3` |
| Z3 | **宫位详情的「AI 宫位解读」也是静态示例 + 假评分条**(score/100 无口径) | `PalaceDetailPanel.tsx` L225 |
| Z4 | **双人对比是 mock**:入口常驻页面,点开是「开发中,敬请期待」+ 示例数据 | `DualChartCompare.tsx` L84-93 `MOCK_PALACES` |
| Z5 | **全站成熟 AI 设施一样没接**:无 `/api/ziwei/stream`、无问答、无缓存/回退/工具链事实注入(八字/K线全有) | `src/app/api/ziwei/` 仅排盘 route |
| Z6 | **零变现零配额**:排盘仅登录+限流,整页无一个付费点,与订阅体系完全脱节 | `api/ziwei/route.ts` |
| Z7 | **漏斗顶端卡死 + 留存断裂**:排盘强制登录(401),游客连盘都看不到;结果只存本地单盘缓存,不入命盘档案体系;埋点仅 3 处 | route SEC-012、`CACHE_KEY` 单盘 |

**一句话诊断:V1 是一张画得很好的空命盘——用户点进任何「解读」,得到的都是别人的命。这比没有解读更伤信任,是本模块口碑与转化的头号杀手。**

### 1.3 用户视角(命理师判断)

紫微用户与八字用户的提问方式不同:八字问「我什么时候发财」,紫微问「**我的夫妻宫怎么样**」「**这十年我走哪个宫**」。紫微的独特卖点是:
1. **宫位化的人生地图**——12 个具体领域天然就是 12 个议题入口,比八字六议题更细颗粒;
2. **四化飞星**——禄权科忌四条因果线,天然的「机会/掌控/名声/功课」叙事;
3. **大限十年一宫**——「人生章节感」,每十年换一个人生主场景,叙事性远强于八字大运干支。

V2 的全部设计都围绕把这三个卖点做成真的。

## 2. 目标与非目标

**目标**(按优先序):
1. **假内容清零**:所有「示例」标签的假解读全部下线,换成真引擎/真 AI。这是底线,先于一切增长设计。
2. **真·大限引擎**:五行局起限 + 顺逆行 + 流年命宫/流年四化,纯本地确定性计算。
3. **逐宫议题式 AI**:点哪个宫解读哪个宫(免费 3 宫/日),全盘详批 VIP 专属——与八字 V2 同一套配额语义与漏斗。
4. **变现闭环**:流年运程表(VIP)+ 全盘详批(VIP)+ 问答(免费 1 次/日尝鲜)。
5. **漏斗与档案打通**:游客可排盘看图,AI 才要登录;命盘接入八字档案体系互跳。

**非目标**:
- 不换排盘流派(维持三合派),不做飞星派/河洛派切换。
- 长生十二神/博士十二神/流曜等进阶星系列为 V2.1(先把主星系解读做真)。
- 双人合盘完整版列为 V2.1,本期只把 mock 入口下线。
- 不做真人服务、不做「化解」类目(伦理红线同 K线 PRD §8)。

**北极星指标**:宫位 AI 解读点击率(排盘完成 → 首个宫位解读生成)。护栏:假内容下线后分享导出率不得下跌(真内容理应更敢分享)。

## 3. 功能设计

### P0-A 真·大限引擎 + 命盘速读(信任地基,零 AI 成本)

**大限引擎** `src/lib/ziwei/dayun.ts`(新):
- 起限岁数 = 五行局数(水二局 2 岁起,木三局 3 岁…火六局 6 岁),`wuxingJuNumber` 现成。
- 行进方向:阳男阴女顺行、阴男阳女逆行(年干阴阳 × 性别),逐宫 10 年,输出 12 大限:`{ 宫名, 宫干支, ageStart/ageEnd, yearStart/yearEnd, 该宫主星, isCurrent }`。
- 流年:当年地支定流年命宫(生年支起法),当年天干查 `SIHUA_TABLE` 得流年四化 + 各自落宫。
- **替换 Z2 假算法**:`DayunSwitcher` 全部接真数据;`lib/utils/dayun.ts` 的线性模板弃用。

**命盘速读卡**(模板合成,置顶,方法论同八字 `quickRead.ts`):
- ①命宫定性:命宫主星组合 + 亮度白话(「紫微天府坐命——自带定盘星气场的格局」;无主星命宫走借对宫口径,明确标注);内置基础格局检测(紫府同宫/杀破狼/机月同梁/日月并明/空宫借星,约 8-10 个,只写正向池)。
- ②身宫与命主身主一句话(数据现成)。
- ③当前大限:「{age} 岁起走{宫名}大限({主星}),这十年的主场景是{领域白话}」。
- 新 `src/lib/ziwei/quickRead.ts` 纯函数 + 单测(边界:空宫命宫/闰月/子时)。

**假内容下线**:`ZiweiAiOverview` 的 `STATIC_TAB_CONTENT` 与 `getDayunContent` 模板、`PalaceDetailPanel` 静态解读区与假评分条,全部删除(评分改为庙旺陷确定性计分并标注口径,或直接去掉)。

**埋点**:`ziwei_paipan_complete` / `ziwei_quickread_show`。

### P0-B 逐宫议题式 AI(转化根基,复用八字全套设施)

- 新 `/api/ziwei/stream`:复用 `src/lib/ai` 模型层 + Redis 缓存 + 双模型回退 + 失败退配额。**prompt 事实注入 = 真实排盘结果**(该宫星曜/亮度/四化 + 三方四正宫位 + 当前大限位置),防幻觉口径同八字工具链。
- **12 宫即 12 个议题**:宫位详情面板底部「AI 深读此宫」按钮流式生成 300-400 字;命盘下方并列六强宫快捷入口:**命宫 / 夫妻 / 财帛 / 官禄 / 迁移 / 福德**。
- 配额:`UsageQuota` 新增 `ziweiAiCount`(迁移 008),免费 **3 宫/日**,游客弹登录;**全盘详批**(十二宫总评长文,即原假「命盘总览」的真实版)VIP 专属。缓存命中不扣配额、生成过的宫位落本地不重复计费——全部沿用八字 V2 行为。
- 结果页构型对齐八字:速读卡(免费)→ 宫格(免费)→ 逐宫 AI(配额)→ 全盘详批(VIP)。
- **埋点**:`ziwei_palace_click {palace}` / `ziwei_palace_ai_click {palace}` / `ziwei_palace_ai_done {palace}` / `ziwei_full_paywall_show`。

### P0-C 漏斗修复:游客可排盘

- 排盘 API 放开登录墙:游客限流(IP 3 次/日)可排盘、看宫格、看速读——排盘是确定性计算,边际成本为零,不该挡在登录后(Z7)。AI 解读才要求登录(401 → 弹登录,现有 `useAiGate` 直接可用)。
- 首屏默认示例盘保留但加「示例盘」水印角标,输入自己生日后消失。

### P1-A 四化飞星叙事卡(确定性,紫微独有卖点)

- 生年四化四颗星各自落宫 → 模板白话四段:**禄(财源在{宫})/权(掌控力在{宫})/科(名声在{宫})/忌(人生功课在{宫})**,每段一句星曜口径 + 一句可执行建议;化忌一律「功课-成长」框架,禁凶祸词。
- `SihuaAnimation` 动画保留,下方叙事由假文换真数据;即原「人生四化」tab 的真实版,零 AI 成本。
- **埋点**:`ziwei_sihua_view`。

### P1-B 流年运程卡(最强付费钩子,对标八字应期表)

- 确定性提取:流年命宫落宫 + 流年四化落宫 → 「今年主题(流年命宫主星)/机会面(流年禄权落宫)/功课面(流年忌落宫)」三行白话。
- **免费:当年运程概要;VIP:未来 10 年流年表**(每年三行),服务端按 `isUserVip` 分层返回,不信任前端(打法同八字 `yingqi`)。
- **埋点**:`ziwei_liunian_view` / `ziwei_liunian_paywall_click`。

### P1-C AI 追问 + 档案打通

- **追问**:通用化 `BaziChatSection` 或新 `ZiweiChatSection`,`/api/ziwei/chat` 复用三层门禁(未登录 401 → 免费 1 次/日(`ziweiChatCount` 或并入 `baziChatCount` 统一「命理追问」额度,倾向后者省一列)→ VIP 不限),事实注入 = 命盘 + 大限 + 流年。
- **档案打通**:紫微页接入八字命盘档案选择器(出生数据同源),排盘后提供「看此人八字 / 人生K线」互跳(信息经 storage 带入);紫微结果随档案持久化,替换现在的单盘 localStorage。
- **埋点**:`ziwei_chat_try {is_vip}` / `ziwei_chat_paywall_show` / `ziwei_to_bazi_click` / `ziwei_to_kline_click`。

### P1-D 命宫人设分享卡

- 分享从「命盘截图」升级「命宫人设卡」:命宫主星 × 格局 → 人设一句话(「紫微坐命——天生的定盘星」「杀破狼——为变化而生的开拓者」),新 `src/lib/ziwei/persona.ts`,14 主星 + 双星组合 + 空宫借星全覆盖,只写正向池;卡面 = 人设标题 + 命盘缩略图 + 五行局 + 二维码(`/ziwei?ref=share`)+ 免责。方法论与实现骨架直接复用八字 `persona.ts` + `ShareCard` 人设版式。
- **埋点**:`ziwei_share_open` / `ziwei_share_export`。

### P2 收尾

- **P2-A 下线双人对比 mock**:入口移除,完整合盘(双盘并排 + 夫妻宫互看)列 V2.1——半成品挂在页面上持续损伤信任(Z4)。
- **P2-B 天马星 + 真太阳时接出生地**:天马(年支三合起马)是常用星,补齐;真太阳时修正接 `CitySearch` 经度(现在参数存在但 UI 没给入口)。
- **P2-C 星曜字典入口强化**:字典是好资产,在宫位详情星曜行加跳转锚点,提高使用率。埋点 `ziwei_dict_open`。

## 7. 风险与表述规范

1. **假内容下线的短期观感风险**:V1 长篇假文「看起来很丰富」,换成真·短解读后页面变「瘦」——用速读卡 + 四化叙事 + 流年卡三张确定性卡补密度,总信息量不降且全部为真。
2. **大限算法口径**:三合派内部起限细节存在门派差异(起限虚岁口径),实现时以主流三合派(局数即起限虚岁)为准,`debug` 字段保留推算依据,便于专业用户核验——这本身就是信任卖点。
3. **表述规范**:化忌/煞星/谨慎大限一律「功课-蓄力-给建议」框架;人设文案只写正向池;禁由任何负面结果导流「化解」消费(同 K线 PRD §8)。
4. **配额语义**:紫微逐宫与八字议题是两个独立额度(`ziweiAiCount` / `baziAiCount`),避免跨模块互相吃额度引发投诉。
