# PRD-合婚页视觉优化 V1（对标 FateMaster 降噪）

> 创建：2026-06-02 11:40 | 产品虾 🦐
> 背景：合婚全量对齐（方案A）已交付，字段功能完整。但视觉「用力过猛」，被竞品 FateMaster 的克制感比下去。Frank 11:37 拍板：P0+P1+P2 全改。
> 目标：在保留功能完整度的前提下，做视觉减法，对标竞品的「呼吸感 + 克制感」，并纠正违反全站设计规范的纯黑底选中态。

---

## 适用范围（强制项：两处同步改）
- 合婚页 `src/app/bazi/marriage/page.tsx`
- 八字主表单 `src/app/bazi/PageClient.tsx`（凡共用控件的样式改动，两处必须一致——全站一致性铁律）
- 复用控件本身（SegmentControl / Select / DatePicker 等）若是共享组件，改组件即可全站生效；若是页面内联样式，两处都要改

---

## P0 — 纠错 + 转化路径（必须，最高优先级）

### P0-1 去除纯黑底选中态（违反全站设计规范）
**问题**：性别「男/女」、日期类型「阳历/农历」的选中态目前是**纯黑底白字**。
**铁律**：MEMORY 全站规范明令——禁止纯黑底选中态，统一用「边框高亮 + 极淡暖底填充」。
**改法**：
- 选中态：边框用赭橙/主色描边（1.5px）+ 背景极淡暖底填充（如 #FAF3EC 或主色 8% 透明度），文字用深色而非反白
- 未选中态：浅灰细边框 + 透明/白底 + 中性灰文字
- 全站所有 SegmentControl 类控件统一此规范（八字主表单同步）
**验收**：性别/日期类型切换，选中态无任何纯黑底；视觉与全站其他选中态一致。

### P0-2 功能三卡移到 CTA 按钮下方
**问题**：「智能匹配 / 全面解析 / 发展参考」三个功能介绍卡当前在「开始合婚」按钮**上方**，打断填表→提交的核心转化路径。
**改法**：将三卡整体移到「开始合婚」按钮**下方**（作为"原理说明/卖点确认"区，用户填完点按钮后才看到）。
**验收**：页面顺序为 表单 → 开始合婚按钮 → 功能三卡 → 分析维度说明。

---

## P1 — 视觉减重（输入控件去噪）

### P1-1 输入框减重
**问题**：每个输入框都有灰底填充 + 粗边框，整页全是框线，显脏。
**改法**：
- 去掉灰底填充，改为白底/透明底
- 边框细化为 1px 浅灰（如 #E5E0D8），聚焦态才用主色高亮
- 整体向「轻量描边 / 下划线风格」靠拢，减少视觉噪音
**验收**：表单区域通透，不再是密集框线堆叠。

### P1-2 「知道出生时间」改 Toggle 渐进展示
**问题**：当前是带橙色图标 + 大段说明文字的独立卡片，像警告框，且关闭时也占大量空间。
**改法**：
- 改为标准 Toggle 开关（iOS 风格 Switch），标签「知道精确出生时间」
- 关闭态：仅显示开关 + 一行极浅灰辅助文字，时分两级选择器/早晚子时**收起不占位**
- 打开态：平滑展开时分两级 + 早晚子时选项
- 辅助说明文字用极浅灰（次要信息隐身），不要橙色图标警告框样式
**验收**：默认（关闭）状态首屏简洁，打开后才展开时间相关控件；男女方对称。

---

## P2 — 呼吸感（间距 + 细节）

### P2-1 放宽行间距
**问题**：模块间垂直间距偏小，挤。
**改法**：表单字段行间距、模块间距整体放宽（参考竞品的疏松排版），给复杂表单呼吸空间。

### P2-2 流程步骤数字改极简
**问题**：流程步骤（1/2/3/4）用黑色实心圆圈数字，生硬。
**改法**：改为空心圆/极简数字 + 细线条，风格轻盈；不要纯黑实心。

### P2-3 分析维度列表加分层容器
**改法**：分析维度列表（基础契合度/性格相容性/婚配宫位/家庭和谐）用一个淡灰/极淡暖底大容器包裹，形成"独立参考信息组"的 Z 轴分层感，而非纯白底散列表。
