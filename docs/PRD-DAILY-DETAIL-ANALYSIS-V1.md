## 1. 背景与目标

### 1.1 为什么做
- 现有 `/daily` 页面提供"今日判词结论"+ 宜忌 + 八字深度分析,但**缺少一层"今日详细解读"**
- 用户看完顶部判词后的最强需求 = "我想知道详细到底是怎么回事"
- 本模块填补这一空缺,并作为 **Pro 转化漏斗的核心钩子**

### 1.2 目标
- **用户价值**:每日提供一份个性化、深度的运势解读,建立"每日打开"的习惯
- **业务价值**:成为免费用户向 Pro 转化的关键触点(限频 + 历史回看)
- **数据指标**:
  - 模块入口点击率 ≥ 60%(基于已进入 /daily 页的用户)
  - 完整阅读率 ≥ 70%(滚动至底部)
  - Pro 转化贡献占 /daily 页的 ≥ 30%

## 5. 内容结构(AI Prompt 输出模板)

**强制 4 段式**,避免 AI 散漫输出:

### 5.1 今日运势综述(约 100 字)
- 总览今日整体气运
- 一句"金句式"判词作为收尾

### 5.2 四维分析(每维 80-120 字)
1. **事业运** - 工作、项目、决策方面
2. **财运** - 进财、破财、投资关注点
3. **感情运** - 单身/有伴侣分别给建议
4. **健康运** - 身体注意事项 + 情绪状态

### 5.3 重点提醒(2-3 条具体行动建议)
- 必须是**可执行**的行动,不要"保持平和"这种废话
- 例:「上午 10-12 点适合签合同」「避免与属虎之人冲突决策」

### 5.4 时辰指引
- 最佳时段(具体到时辰)+ 适合做什么
- 需避开时段 + 避开原因

## 6. 技术实现

### 6.1 后端 API

#### 6.1.1 生成接口
```
POST /api/daily/detail-analysis
Body: {
  user_id: string,
  date: "YYYY-MM-DD"  // 默认今日
}
Response: SSE Stream(流式输出)
```

**逻辑**:
1. 鉴权 + 检查今日是否已生成(免费用户)
2. 读取用户八字数据(从 user_bazi_profile 表)
3. 计算当日干支 + 流年信息
4. 拼接 Prompt(含 4 段式结构约束)
5. 调用 LLM(建议 Claude Sonnet / GPT-4,流式返回)
6. 写入 `daily_detail_history` 表

#### 6.1.2 历史记录接口
```
GET /api/daily/detail-history?limit=3|all
Response: [{ id, date, summary, full_content }]
```

**逻辑**:
- 免费用户:limit 强制为 3
- Pro 用户:可传 all 或更大 limit

### 6.2 数据库

```sql
CREATE TABLE daily_detail_history (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL,
  date DATE NOT NULL,
  summary TEXT,            -- 综述段(用于历史列表展示)
  full_content TEXT,       -- 完整 4 段内容(JSON 或 Markdown)
  llm_model VARCHAR(64),
  generated_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(user_id, date)    -- 同一天只保留一条(重新生成会覆盖)
);
CREATE INDEX idx_daily_detail_user_date ON daily_detail_history(user_id, date DESC);
```

## 7. Loading 体验设计

### 7.1 流式输出(必须)
- 后端用 SSE 推送 token 流
- 前端逐字渲染(光标闪烁动效)
- 用户感知"AI 在认真思考",等待焦虑降 70%

### 7.2 Loading 文案 3 段切换
| 时间 | 文案 |
|------|------|
| 0-3s | "正在为您调取今日命盘..." |
| 3-8s | "AI 正在结合八字与流年分析..." |
| 8s+ | "正在生成专属解读..." |

### 7.3 时长目标
- 总时长:8-15 秒(首字 token < 2s,全部完成 < 15s)
- 超时降级:> 30s 显示"网络慢,请稍后重试"
