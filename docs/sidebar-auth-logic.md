# 侧边栏（Sidebar）登录状态与订阅逻辑 — 产品需求文档

> 作者：产品虾 | 日期：2026-04-14 | 状态：待开发
> 参考：FateMaster 侧边栏交互设计

---

## 1. 需求背景

当前 CyberFate 侧边栏缺少基于登录/订阅状态的差异化展示。需要实现三种状态的侧边栏底部区域，引导用户完成登录和订阅转化。

## 2. 三种用户状态定义

| 状态 | 条件 | 标识 |
|------|------|------|
| **未登录** | 无有效 token / session 过期 | `guest` |
| **已登录·未订阅** | 有 token，但无活跃订阅 | `logged_in` |
| **已登录·已订阅** | 有 token + 活跃订阅（免费试用期内也算已订阅） | `subscribed` |

> 注：免费试用期内的用户视为 `subscribed`，不显示付费引导。

## 3. 侧边栏底部区域 — 三态设计

### 3.1 状态A：未登录 (`guest`)

```
┌─────────────────────────┐
│  （功能导航列表...）      │
│                         │
│  ┌───────────────────┐  │
│  │  🔓 解锁全部功能   │  │  ← 黑色实心按钮 (primary CTA)
│  └───────────────────┘  │
│                         │
│  ┌───────────────────┐  │
│  │  👤 登录 / 注册    │  │  ← 白底描边按钮 (secondary)
│  └───────────────────┘  │
└─────────────────────────┘
```

**交互逻辑：**
- 点击「解锁全部功能」→ 跳转 `/pricing`（定价页）
- 点击「登录 / 注册」→ 弹出登录弹窗 或 跳转 `/login`
- **两个按钮都展示**，因为未登录用户需要同时看到价值主张和登录入口

### 3.2 状态B：已登录·未订阅 (`logged_in`)

```
┌─────────────────────────┐
│  （功能导航列表...）      │
│                         │
│  ┌───────────────────┐  │
│  │  🔓 解锁全部功能   │  │  ← 黑色实心按钮 (primary CTA)
│  └───────────────────┘  │
│                         │
│  ┌──── ───────────────┐ │
│  │  [头像]  feng.5166  │  │
│  │          feng@xx.com│  │
│  └─────────────────────┘│
│  ┌───────────────────┐  │
│  │  👤 个人资料       │  │  ← 文字链接/浅底按钮
│  └───────────────────┘  │
│  ┌───────────────────┐  │
│  │  ↪ 退出登录        │  │  ← 文字链接/浅底按钮
│  └───────────────────┘  │
└─────────────────────────┘
```

**交互逻辑：**
- 显示用户头像 + 用户名 + 邮箱（头像优先用 OAuth 头像，无则取首字母）
- 「解锁全部功能」→ 跳转 `/pricing`
- 「个人资料」→ 跳转 `/profile` 或弹出个人资料面板
- 「退出登录」→ 清除 token → 刷新页面回到 `guest` 态

### 3.3 状态C：已登录·已订阅 (`subscribed`)

```
┌─────────────────────────┐
│  （功能导航列表...）      │
│                         │
│  ┌──── ───────────────┐ │
│  │  [头像]  feng.5166  │  │
│  │          feng@xx.com│  │
│  │    ✅ Pro 会员      │  │  ← 订阅标识（小 tag）
│  └─────────────────────┘│
│  ┌───────────────────┐  │
│  │  👤 个人资料       │  │
│  └───────────────────┘  │
│  ┌───────────────────┐  │
│  │  ↪ 退出登录        │  │
│  └───────────────────┘  │
└─────────────────────────┘
```

**交互逻辑：**
- **不显示「解锁全部功能」按钮** — 用户已付费，不需要再看到转化入口
- 用户信息区增加一行小字显示订阅状态：「✅ Pro 会员」或「✅ 会员有效期至 YYYY-MM-DD」
- 其余同状态B

## 4. 功能列表区域的锁定状态（可选 P1）

> 此部分为增强体验，P0 可只做底部区域三态切换。

当用户处于 `guest` 或 `logged_in`（未订阅）状态时，部分高级功能可显示锁定图标：

| 功能项 | 免费用户 | 付费用户 |
|--------|---------|---------|
| 八字计算 | ✅ 可用 | ✅ 可用 |
| 八字合婚 | 🔒 锁定 | ✅ 可用 |
| 每日运势 | ✅ 可用（每日1次） | ✅ 无限 |
| 紫微排盘 | 🔒 锁定 | ✅ 可用 |
| 梅花易数 | 🔒 锁定 | ✅ 可用 |
| 六爻 | 🔒 锁定 | ✅ 可用 |
| 塔罗牌 | ✅ 可用（每日3次） | ✅ 无限 |
| AI 老黄历 | 🔒 锁定 | ✅ 可用 |

**锁定态交互：**
- 功能名右侧显示小锁图标 🔒（muted 色，14px）
- 整行 `opacity: 0.6` + `pointer-events: none`（不可点击）
- hover 时 tooltip 提示：「升级会员解锁此功能」

> ⚠️ 具体哪些功能收费、哪些免费，以最终定价策略为准。以上为建议。

## 5. 技术要点

### 5.1 状态获取
- 前端从 cookie / localStorage / context 获取登录态
- 订阅状态通过 `/api/user/subscription` 接口查询（或 JWT payload 中携带）
- 首次渲染时可用缓存状态，异步请求更新

### 5.2 组件拆分
建议拆分为：
- `SidebarNav` — 功能导航列表（与状态无关）
- `SidebarFooter` — 底部区域（接收 `authStatus` prop，三态渲染）
- `UserCard` — 用户信息卡片（状态B/C 共用）

### 5.3 设计规范（对齐 Design Tokens v6）

| 元素 | 规范 |
|------|------|
| 「解锁全部功能」按钮 | `bg-[#1C1A16] text-white rounded-lg py-3 px-4 w-full font-medium` |
| 「登录/注册」按钮 | `border border-[#E5E2DD] rounded-lg py-2.5 px-4 w-full text-[#1C1A16]` |
| 用户信息区 | `py-4 px-3 flex items-center gap-3` |
| 头像 | `w-10 h-10 rounded-full bg-[#F0EDE8] flex items-center justify-center text-[#1C1A16] font-medium` |
| 个人资料/退出登录 | `py-2 px-3 text-sm text-[#6B6560] hover:text-[#1C1A16] cursor-pointer` |
| 订阅 Tag | `text-xs text-green-700 bg-green-50 px-2 py-0.5 rounded-full` |

### 5.4 响应式
- 移动端侧边栏以 Drawer/Overlay 形式展现，底部区域逻辑一致
- 底部区域固定在侧边栏最底部（sticky bottom）

## 6. 验收标准 (Acceptance Criteria)

### P0 必须实现
- [ ] 未登录时显示「解锁全部功能」+「登录/注册」两个按钮
- [ ] 已登录未订阅时显示「解锁全部功能」+ 用户信息（头像/邮箱）+ 个人资料 + 退出登录
- [ ] 已登录已订阅时不显示「解锁全部功能」，显示用户信息 + 订阅标识 + 个人资料 + 退出登录
- [ ] 点击「解锁全部功能」跳转到 `/pricing`
- [ ] 点击「登录/注册」触发登录流程
- [ ] 点击「退出登录」后正确清除登录态并刷新 UI
- [ ] 移动端 Drawer 内表现一致

### P1 增强体验
- [ ] 免费用户看到的功能列表中，付费功能带锁定图标和弱化样式
- [ ] 锁定功能 hover 时提示升级
- [ ] 用户头像优先显示真实头像，降级为首字母
- [ ] 订阅用户显示会员有效期
